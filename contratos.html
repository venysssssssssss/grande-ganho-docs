Contratos e handoff ​

Referência executável ​

A API usa REST JSON em /v1. Schemas TypeBox definem entrada, DTOs e OpenAPI; o cliente TypeScript deve consumir o artefato gerado pela entrega, não reproduzir tipos manualmente. O OpenAPI JSON desta entrega registra métodos, parâmetros e schemas das rotas implementadas; a matriz de telas distingue a API confirmada das capacidades futuras. Esse contrato não comprova implantação cloud ou capacidade de carga.

Gerar o contrato com npm run contracts:generate antes de npm run docs:build. O JSON público é uma cópia explícita do contrato gerado; nenhuma outra saída de build ou fonte privada é copiada com ele. A API também fornece /v1/openapi.json conforme sua política de autenticação.

Não há documentação pública de dados reais, URLs internas, IDs de projetos ou credenciais. Exemplos abaixo são sintéticos e descrevem semântica; não são respostas capturadas de produção.

Data observada e data registrada são diferentes: a primeira diz quando o fato ocorreu; a segunda quando foi recebido. O frontend não calcula frescor usando apenas a hora em que baixou a resposta. Progresso conhecido de 0% não deve virar "Sem plano".

Listas e falhas ​

Paginação por cursor, limite máximo e ordenações em allowlist. O cursor pertence à consulta e ao escopo atual; mudar filtro exige reiniciar a paginação. Filtros desconhecidos devem ser rejeitados ou tratados conforme schema, nunca concatenados a SQL. Campo de ordenação não define permissão.

Erros são estruturados e têm código estável, mensagem segura e identificador de requisição. Detalhes de SQL, stack, concessões ocultas, conteúdo pessoal e nomes de arquivos privados não entram na resposta. O schema gerado é a autoridade do formato exato.

Idempotência e concorrência ​

Uma intenção de usuário recebe uma Idempotency-Key; tentativas da mesma intenção reutilizam a chave e payload. Uma nova intenção usa outra chave. Não gerar outra chave automaticamente quando a rede cair depois do envio: o servidor pode ter confirmado a mutação.

O contrato informa operações idempotentes e validade da chave. Mudanças concorrentes usam version. A UI não resolve conflito por "último clique vence". O cliente pode oferecer comparação entre versão atual e rascunho, mas a decisão precisa ser explícita.

Upload e evidência ​

Evidência passa por autorização, limite de bytes, allowlist de tipos e quarentena. Extensão e Content-Type informados pelo cliente não provam conteúdo. Malware deve ser inspecionado antes de servir o objeto; estado pendente ou recusado nunca gera download válido.

Não guardar URL de objeto como autorização permanente. O backend reavalia escopo e concessão ao servir. Se o mecanismo real for URL temporária, sua janela de exposição precisa estar documentada e ser curta; para conteúdo pessoal revogável, streaming autenticado é preferível. Remover evidência inclui objeto, metadados e caches autorizados.

Android online e web ​

O primeiro Android é online e usa a mesma API do desktop. Não há APK nem sincronização offline nesta entrega. A camada de autenticação armazena bearer opaco em recurso nativo seguro; tokens de identidade não ficam em logs de depuração.

Web usa cookie seguro com CSRF nas mutações e origem/CORS restritos. O frontend não lê o cookie HttpOnly. Troca de organização, logout e revogação invalidam consultas e caches. Conteúdo pessoal não entra em service worker, analytics, crash report ou notificações de tela bloqueada.

Estados obrigatórios: carregando, vazio, desconhecido, desatualizado, erro recuperável, acesso recusado, sessão expirada, conflito e job pendente/falho. Tabelas grandes usam paginação; detalhes só carregam quando necessários. Acessibilidade: nomes de campos, foco preservado, erro associado ao campo, navegação por teclado e texto além de cor.

Futuras capacidades ​

IA deverá preservar fontes e revisão humana, sem extrair nota pessoal de transcrição como fato. WhatsApp exige integração oficial, consentimento/finalidade e política de retenção; não usar sessão pessoal ou scraping. Networking exige controle sobre exposição de contato. Encantamento exige aprovação humana de compra e orçamento. Portal do mentorado exige escopo de titular distinto do papel de equipe.

Push, iOS e offline têm contratos próprios de privacidade e sincronização. Só entram quando autorizados e implementados; a existência do backend não significa autorização de disponibilizar dados a aplicativos externos.
